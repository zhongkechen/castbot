# [P2] UPnP notifications cannot parse valid tokens

## Problem and prerequisites

After UPnP is configured and playback starts, the device sends notifications to the application's generated `/upnp/notify/{local_token}` callback URL. The URL contains a hexadecimal token.

Expected: a registered token reaches notification handling, and a normal event receives a successful response. Observed: a valid token containing a–f returns HTTP 400. A valid token containing only digits is first converted to int, then passed to `int(value, 16)`, which raises TypeError. Playback-state notifications and recovery after a stream interruption therefore cannot work.

The reproducer submits two registered tokens generated by the real LocalToken to the real `UpnpNotifyServer.handle`, confirming that both fail before the request body is read.
